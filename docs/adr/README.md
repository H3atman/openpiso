# Architecture Decision Records

Decisions from the OpenPiso **expansion phase** (accounts, points, vouchers,
tamper response). The MVP is shipped; these ADRs extend it and, where noted,
deliberately relax MVP constraints.

| ADR | Decision |
|-----|----------|
| [0001](0001-time-ownership.md) | Time belongs to the PC for guests, to the account when logged in; account is the source of truth and what the timer decrements. Claim absorbs PC guest time; logout takes time with the customer. |
| [0002](0002-account-session-binding.md) | One account = at most one active session. Logging in elsewhere auto-kicks the prior PC. Server owns the binding. |
| [0003](0003-points-economy.md) | Points are a ~10% loyalty bonus (guests earn none). Each Redemption Tier has a live **Effective Bonus %**; the most generous tier drives the headline warning. Wheel has a configurable house edge. |
| [0004](0004-account-authentication.md) | Username + password, local only. Weak security accepted (neighborhood shop). Owner resets passwords. Hash passwords; audit sensitive actions. |
| [0005](0005-tamper-response-and-expiry-powraoff.md) | Money is server-safe regardless of the client. Watchdog (in the diskless image) restarts a killed client. At 0, the PC **powers off** — diskless reboot wipes the prior customer for privacy. |
| [0006](0006-session-lifecycle.md) | A crash is not a logout; session survives and keeps burning. Restart forces re-login. Idle drain is intended — logging out is how customers protect their balance. |
| [0007](0007-pc-level-takeover.md) | A new login takes over a PC; the displaced account keeps its portable balance. Completes the displacement model (unique on both account and PC axes). |
| [0008](0008-coin-routing-central-terminal.md) | One central terminal; pick a PC; the coin routes to the logged-in account (time + points) or the PC as guest (zero points). |
| [0009](0009-vouchers.md) | Owner-minted, single-use, atomic, account-only. Two kinds: `sold` (revenue) vs `promo` (cost). |
| [0010](0010-account-creation.md) | Accounts created via self-service sign-up and admin. Junk accounts ignored. "Guest accounts" = anonymous guest mode, not an entity. |
| [0011](0011-admin-authority.md) | Single owner password (no staff roles yet). Account deletion is a soft delete; history preserved, balance forfeited, session ended. |
| [0012](0012-spin-the-wheel.md) | 1 point = 1 spin; prizes are time / nothing / capped free-spin chain, never points. Server-authoritative. House edge is measured against the most generous Redemption Tier, shown live in settings. Owner kill-switch. |
| [0013](0013-balance-and-session-durability.md) | Balance written to SQLite every second; crash errors favor the customer; session bindings are in-memory only, so a server restart kicks everyone to login with balances intact. |
| [0014](0014-reporting-model.md) | Top line = cash in (coins + sold vouchers); free time dispensed is a separate cost line; track outstanding points liability; per-period/account/PC slicing requires consistent event categorization from day one. |
| [0015](0015-audit-log.md) | One append-only, strongly-typed event stream is the source of truth for who-did-what **and** reporting. Records actor + honest session-end reasons + failures/denials. No app-side edit/delete; retained forever; reviewable with filters + export. |
| [0016](0016-diagnostic-logging.md) | Diagnostic logs are a separate store (rotating `tracing` files, ~7-day cap); diskless clients forward meaningful diagnostics to the server; routine noise evaporates. The forwarding path is decided in ADR-0078, which supersedes the proposed interleaved Logs-screen viewer. |
| [0017](0017-username-identity.md) | Usernames preserve display spelling but use validated ASCII lowercase identity for case-insensitive login and permanent uniqueness. |
| [0018](0018-canonical-audit-compatibility.md) | Legacy financial tables remain one-to-one detail tables linked to the canonical audit event; migration avoids duplicate events. |
| [0019](0019-points-earn-carry.md) | ~~Logged-in purchases carry sub-threshold paid cents toward future whole points; guest purchases earn no points and no carry.~~ Superseded by ADR-0038. |
| [0020](0020-voucher-recognition-and-expiry.md) | Sold-voucher cash is recognized at owner mint/sale recording; redemption credits prepaid value. Voucher expiry is nullable and omitted by default. |
| [0021](0021-manual-adjustment-target.md) | ~~Manual adjustments remain PC-bound (Guest Time only); account balance corrections flow through the existing typed mutation paths so audit categorization stays unambiguous.~~ Superseded by ADR-0069 (the PC-bound rule survives there). |
| [0022](0022-expiry-grace-period.md) | Expiry shows a non-blocking low-time warning (≤120 s), then a blocking 30 s shutdown grace countdown that a top-up cancels; the client performs the real OS power-off (release builds only). Server-authoritative `power_state` on `pc.updated`. |
| [0023](0023-serial-coin-input-and-terminal-selection.md) | v1 coin input is a COM-port acceptor read by the admin process, gated by a single server-owned terminal selection. Set pin is fail-closed (selection-first lock); each coin commits immediately; pulses→pesos by a configurable gap-batched map; offline PCs are selectable (preload Guest Time). Refines ADR-0008. |
| [0024](0024-web-admin-sole-owner-surface.md) | The desktop console is retired; `:8080/admin` (Svelte + shadcn-svelte) becomes the sole owner surface with full parity over authenticated HTTP. Its unhardened owner-session decision is superseded by ADR-0074. |
| [0025](0025-terminal-selection-commit-flow.md) | The numpad-driven Central Terminal opens a Selection Window on `Enter` (no confirm screen); the insert-screen `Enter` is context-sensitive — cancel-and-close when no coin is in, confirm when money has landed — and cancel now closes the window instead of waiting out the inactivity timeout. Frontend-only; refines ADR-0023. |
| [0026](0026-central-terminal-grid-ui.md) | The Central Terminal grid screen is a departures-board layout: small header, large hero mirroring the typed PC number, and a 5-column grid of every PC with a status-colored emphasized border, the time on the clock, and the account username. Pressing Enter on an unavailable PC auto-deletes the typed number with a brief shake. No on-screen Backspace/Clear buttons (the numpad has them). |
| [0027](0027-client-lock-and-owner-pin-gate.md) | The seated customer is untrusted; the client Fullscreen Lock genuinely blocks (no customer Quit, no minimize-to-tray, re-asserts on blur). Owner access to client backend settings + Quit is gated by a server-sourced, hashed **Owner PIN** (shared across PCs), verified server-side with a locally cached hash for offline fallback. No owner/admin account role. |
| [0028](0028-client-kiosk-os-hardening.md) | Overrides the no-OS-hardening stance (explicit owner approval): kiosk lockdown via Windows **Assigned Access / Shell Launcher v2** (owner provisioning) + app-level soft hardening (keyboard-hook suppression, re-assert-on-blur). Optional PIN-gated sign-out policy writes three release-Windows registry values; Ctrl+Alt+Del Restart / Shut down remain available. Ctrl+Alt+Del is otherwise mitigated only by provisioning, never app code. No system tray (no shell). The Owner PIN must survive lockdown. **Amended 2026-08-01:** adds window-level prevention — static `skipTaskbar`, a refused `WM_CLOSE` unless `initiate_exit` authorized it, and an all-modes but foreground-scoped Alt+F4 hook. Task Manager and Assigned Access are untouched. |
| [0029](0029-client-window-model.md) | One reconfigured window, three views (borderless-maximized Lock, Widget, Mini Bar). Auth lives on the Lock; usable Guest Time auto-enters the persisted Widget/Mini Bar View Mode. Guest Log in sets one transient frontend-only route to Lock with return-to-session; no guest-entered flag exists. Authoritative Lock conditions override it; its former connection-loss-keeps-time rule is superseded client-side by ADR-0045. |
| [0030](0030-account-transfers.md) | Account-to-account transfers split by currency: **time** transfers are immediate, atomic, and server-authoritative; **points** transfers are owner-confirmed via a single-use, time-boxed 6-digit code (customer-presented, direction A) with DB-backed pending requests. Owner confirmation is the control against points funnelling. |
| [0031](0031-client-config-persistence-and-pc-identity.md) | The client persists its config (`server_url`, `view_mode`, and the server-resolved cached `pc_id`) to a Rust-owned JSON file read before auto-connect; the frontend never touches it. Server **owns PC identity**, keyed on a client-reported **MAC** with server-captured **IP** as a one-time bootstrap: MAC-match → identity; else preconfigured-IP match with `mac_address IS NULL` → bind MAC; else reject. There is no auto-create and no pending/adopt flow. MAC is an identity hint, not an auth secret. |
| [0032](0032-account-session-extractor.md) | LAN account auth becomes an `AccountSession` extractor mirroring `OwnerSession`: the account token moves from the request **body** to an `Authorization: Bearer` header so a `FromRequestParts` guard enforces auth by type, not by a hand-called helper. The redundant body `pc_id` cross-check is dropped (token is authoritative). Rejection mirrors `OwnerSession` (`(StatusCode, String)`, no error-boundary dependency); denials are intentionally **not** audited (benign stale-token races). Flag-day cut, no shim. |
| [0033](0033-typed-coin-source-trust-and-coin-outcome.md) | Device trust on the coin path becomes a typed `CoinSourceClaim` (serial terminal / simulator / remote-device-with-secret) that subsumes device identity, flows from the request edge through `sessions` unchanged, and is **authenticated inside** the coin-event transaction — deleting the `trusted_local_serial` bool and both twin-wrapper pairs. The HTTP edge can never construct the serial-terminal variant (type-level spoof-guard) with an in-tx backstop kept. The routing **consequence** is extracted to a pure `CoinOutcome` in core (guest→0 points); the routing **target** stays in `sessions` under the binding lock. Two behaviour-preserving commits. Reconciles ADR-0008 and ADR-0023. |
| [0034](0034-connected-zero-time-shutdown-and-channel-consistency.md) | Any **connected** PC at zero Remaining Time runs the grace countdown and powers off — including a fresh boot that never held time; the positive→zero transition rule (ADR-0005/0022) is dropped. `power_state` becomes a pure function of status + Remaining Time (no per-PC tracking) and is stamped at one chokepoint that **returns** the value, so the heartbeat HTTP response, disconnect response, and SSE snapshot/updates all agree — fixing a latent bug where the heartbeat's stale `active` re-armed the client grace deadline and the countdown never completed. Client unchanged. |
| [0035](0035-centralized-theme.md) | One shop-wide accent + per-surface light/dark, stored server-side (`theme_settings` singleton, integer version) and applied live via a pure TS "anchor snap" ramp generator in `packages/ui` — fixed lightness anchors take only hue/scaled-chroma from the pick, so contrast is structural. Delivery rides existing channels (heartbeat version stamp, kiosk Tauri push, web-admin poll); browser-local ThemeToggle deleted. Deliberately **no audit event** (cosmetic, single-owner). |
| [0036](0036-kiosk-in-use-top-ups.md) | Kiosk availability means reachable and not owner-locked: `online` and `in_use` PCs are selectable; `offline` and `locked` remain blocked. Supersedes ADR-0023's offline-preload rule and ADR-0026's online-only rule; server routing is unchanged. |
| [0037](0037-contention-safe-password-change.md) | Password Change performs Argon2 work outside SQLite and conditionally replaces the exact verified hash. Concurrent changes are first-writer-wins; sessions persist; success audit is atomic; stale audit is best-effort; HTTP errors are customer-safe. |
| [0038](0038-fractional-points-centipoints.md) | Points become integer **centipoints** (1/100 pt): earning is fractional and direct (supersedes ADR-0019's carry, which shrinks to centicent dust), displayed with two decimals. Wheel spins stay 1.00 pt; transfers/adjustments/vouchers allow 0.01. Wire fields renamed `*_centi`; migration backfills ×100 and pays out existing carry at the going earn rate. |
| [0039](0039-redemption-tiers.md) | Guaranteed redemption is 1–20 owner-authored whole-points/whole-minutes tiers, sorted by points. Upgrade seeds the former pair exactly; the most generous tier drives Effective Bonus % and wheel safety math. Supersedes ADR-0038's whole-batch redemption language. |
| [0040](0040-voucher-batch.md) | Voucher Batch: generate 1-1000 vouchers in one action with prefix, suffix, uniform values, optional expiry. Batch-sold cash recognised at redemption. Batch-level void. Single audit event per batch. |
| [0041](0041-voucher-template.md) | One shop-wide owner-authored Voucher Template; escaped token substitution in sandboxed owner-browser preview/print iframes, with no JavaScript execution. |
| [0042](0042-single-voucher-inference-and-void.md) | Single Voucher kind is inferred from cash server-side; active Vouchers may be individually voided with retained audit/history and no automatic revenue reversal. |
| [0043](0043-coin-ingestion-sampling-and-observability.md) | A dedicated ~30 ms Pulse Sampler feeds the 500 ms selection loop; refused Inhibited Pulses stay inert while buffered trains may straddle Set Pin inhibition, Coin Trace Ids live in audit metadata, and the owner bundle is bounded and structurally redacted. Refines ADR-0023. |
| [0044](0044-immediate-write-transactions-and-pc-removal.md) | Every read-then-write transaction begins `BEGIN IMMEDIATE` (+ 5 s `busy_timeout`) so contending writers queue instead of failing with `SQLITE_BUSY`, fixing `database is locked` on settings saves at the root. Adds clean-only hard removal of a PC row (no coin/adjustment/audit/wheel history, zero time, not online); rows with history are hidden instead. `pc_removed` and the pre-existing PC lifecycle events carry the id in metadata with a null FK `pc_id` so an append-only, FK-protected audit row can never pin a removable pcs row. |
| [0045](0045-offline-shutdown-countdown.md) | A previously-connected Client that loses the admin server immediately returns to the Fullscreen Lock and arms an Offline Shutdown Countdown using cached Offline Grace. Its absolute deadline is atomically persisted for relaunch, expired-on-launch gets a 10-second re-warning, and owner-unlocked settings pause it with a persisted extension on resume; reconnect cancels and deletes it. Disconnected Clients are never routable to Widget/Mini Bar; release Windows builds reuse the Rust one-shot shutdown path, while debug/non-Windows builds log only. Setup, connecting, unregistered, and never-connected states do not arm. |
| [0046](0046-spin-the-wheel-points-prize.md) | Points become a legal Spin the Wheel prize, superseding ADR-0012's "never points" rule. The points axis has no guardrail (deliberate asymmetry); time-axis guardrail survives. Compensating control: Points Minted by Wheel report line. |
| [0047](0047-equal-slice-wheel-segments.md) | Wheel Segments lose their probability weight: every segment is `1/n` of the circle and, while Bokya Rate is unset, `1/n` likely. Rarity within Bokya/non-Bokya groups is expressed by duplicating a prize. Slices render a derived prize line the label cannot contradict. The existing spin-path house-edge gate remains, and ADR-0047 adds a tab-load warning. ADR-0049 supersedes the equal-likelihood guarantee when Bokya Rate is set. |
| [0048](0048-client-guard-tamper-kill.md) | A **Client Guard** Windows service (SYSTEM, shipped in the Client installer) holds a named pipe the Client keeps open; a drop without a clean-exit message or OS shutdown is a **Tamper Kill** — crashes included, deliberately. Relaunch is immediate then backs off and never gives up. The relaunched Client reports on its heartbeat (persisted and retried offline); the **server** attributes against Account Session history at a receipt-anchored kill instant (`subject: account｜guest｜none｜unknown`), never the device. The session ends as `tamper_kick` with balance and points **untouched**, and a guest with preserved Guest Time must explicitly continue from the neutral Lock; an idle PC is `none`; no tamper warning is shown. Audit feed only; a PIN-gated owner quit disarms the Guard for that boot. Implements ADR-0005's never-built watchdog. **Amended 2026-08-01:** "prevention is settled and closed" narrowed — window-level prevention moved to ADR-0028 §3; a refused close is a non-event on the pipe and the tamper model is unchanged. **Amended 2026-08-05:** SSE waits for the report heartbeat; guest Tamper Kicks require explicit continuation. |
| [0049](0049-bokya-rate.md) | An optional owner-set **Bokya Rate** biases the server-side draw while slices remain equal, deliberately inverting ADR-0047's truthful-geometry guarantee. Unset remains uniform; duplication distributes prizes within Bokya/non-Bokya groups; derived prize lines and time-axis safety checks survive. |
| [0050](0050-web-admin-pin-rotation.md) | An authenticated owner may rotate the Web Admin PIN after proving the current PIN; the caller Owner Session survives while all others are revoked. ADR-0074 additionally ends every Remote Control Session. |
| [0051](0051-web-admin-url-routing.md) | Web Admin URLs are authoritative real History API paths under `/admin/`, with hand-written routing, URL-preserving login, distinct not-found and Settings fallback rules, and a URL-subordinate 24-hour last-route restore. |
| [0052](0052-coin-promo.md) | **Coin Promo**: owner-authored bonus time added *on top of* the base rate for a coin routed to an Account, matched on the **exact** coin amount. Guests get nothing and a later Claim never back-credits (ADR-0003's rule for points). Coin events only — never vouchers, adjustments, redemptions, or wheel. `seconds_added` stays the total; the bonus is recorded separately and reported under Free Time Dispensed while cash stays Cash Revenue (ADR-0014). Effective Bonus % extends to promo rows with an account worst case combining promo + Redemption Tier; advisory, never blocking. Ships disabled with no rows. |
| [0053](0053-shop-hours.md) | **Shop Hours**: a seven-day schedule with overnight **Open Period** tails, **Last Call**, absolute-expiry **Shop Override** states, and one computed **Shop Status**. Closing is soft: it gates entry and new value but never ends Active Sessions or touches balances; the Set Pin stays the physical coin boundary. Uses Admin host local time, with no shop timezone. |
| [0054](0054-backup-and-restore.md) | **Backup** is a readable self-describing `.sql` artifact; the fail-closed **Pre-Migration Backup**, not the schedule, is the load-bearing protection against bad updates. The filesystem-derived **Backup Catalog** has no table; **Backup Set** selection shapes dumps but never restore; **Staged Restore** whole-database replacements apply on next launch. |
| [0055](0055-central-terminal-autostart.md) | **Autostart**: an owner toggle that makes the Central Terminal launch at Windows **logon** via the per-user `Run` key (`tauri-plugin-autostart`), not at boot — unattended recovery still needs owner-provisioned autologon, which OpenPiso documents but never configures. The registry is the sole source of truth (no `settings` row, no mirror), the toggle is read-only in debug builds, and both success and failure are audited. `tauri-plugin-single-instance` ships with it, because autostart makes a second admin process — two timer loops on one database — likely. The host boundary is a trait so the handler is testable without a registry. |
| [0056](0056-kiosk-lock-always-on-top.md) | **Kiosk Lock**: the Central Terminal window boots always-on-top (`alwaysOnTop` in config *and* re-asserted in Rust setup) and the state is ephemeral — every launch starts locked, with no `settings` row and no Web Admin toggle. Release is a hidden double-click on the Shop Name plus the owner PIN, inert while a Selection Window is open; re-engaging needs no PIN and never clears the throttle. Rust owns both the PIN check and the flag (no `core:window:allow-set-always-on-top`), releases are audited under their own event types rather than as Web Admin logins, and the header dot is the always-on-top signal. |
| [0057](0057-account-import-from-legacy-systems.md) | Owner Account Import from a Martec export: dry-run and commit share one plan, valid rows commit atomically with non-cash audit provenance, conflicts are never overwritten, and imported bcrypt credentials upgrade on first login. |
| [0058](0058-audit-derived-web-admin-notifications.md) | Web Admin Notifications are a 30-day derived view over the Audit Log with a fixed Alert/Notice classifier, global Notice watermark, per-Alert acknowledgement, 15-second polling, and no parallel event table. |
| [0059](0059-account-import-reuses-deleted-usernames.md) | Account Import may reuse the Username of any deleted Account by creating a new Account identity; the deleted identity/history remain, while active conflicts and normal creation/signup remain rejected. |
| [0060](0060-coin-20-calibration-capture.md) | Fresh installs receive a candidate ₱20 pulse mapping; owner-only physical calibration shares the live serial sampler, captures five non-transactional samples, and applies only consistent evidence. |
| [0061](0061-account-login-throttle.md) | Account login only: normalized Usernames get a flat, repeatable 60-second lockout after ten consecutive failures; state is in-memory and never escalates. |
| [0062](0062-account-session-history.md) | Account Session history is durable record, not live state: starts/ends share transactions with their Audit Log events, and startup closes open rows as `server_restart` at the last known PC heartbeat without manufacturing end events. |
| [0063](0063-unmapped-pulse-count-typed-batch-read-outcome.md) | Superseded by ADR-0070: historical unmapped rejection rows remain supported, but live `Unmapped` batch reads are removed in favor of fixed pulse-sum authority. |
| [0064](0064-owner-visible-coin-loss-notices.md) | Historical boundary retained by ADR-0070: Inhibited Pulses remain observable; existing Coin Batch Rejection rows remain readable and creditable, but current pulse-sum acceptance produces no new mismatch rows. |
| [0065](0065-phone-designed-vs-phone-tolerable-owner-screens.md) | Web Admin screens are **phone-designed** or **phone-tolerable**; below 768px the former use JavaScript-branched `ResponsiveRows` cards, overlays convert by width, touch density changes stay phone-only, and the bare Settings path alone gets a phone section index. |
| [0066](0066-shop-rate.md) | **Shop Rate** is the owner-configurable paid-time exchange; changes append a new rate and retire the previous one, economy guardrails warn but never block, and no scheduled or time-of-day rates exist. Integer-division truncation applies and committed time is never recomputed. |
| [0067](0067-paged-phone-lists-and-mobile-settings-navigation.md) | Paged phone-designed lists slice above `ResponsiveRows` so both branches still iterate one identical collection; mobile Settings navigation keeps its collapsible submenu instead of restoring the old gate. |
| [0068](0068-owner-sign-out.md) | **Owner Sign-Out** ends an Active Session from the dashboard with a logout's exact lifecycle, but the two durable records diverge on purpose: session history records `end_reason = 'logout'` so reports and attribution do not fork, while the Audit Log records `owner_sign_out` with the `admin` actor so the log never claims the customer left voluntarily. Keyed on `session_id`, allowed on an unreachable PC, Silent. |
| [0069](0069-rejection-credit.md) | **Rejection Credit**: an owner re-credit of a coin the acceptor took but never valued, always linked to a specific **Coin Batch Rejection** row. Attribution is frozen at that row (recorded Account, else that PC's Guest Time; refused if the Account was deleted); the amount comes from the **Pulse Map**, never free text; value is computed exactly as an accepted coin's (Shop Rate + Points + Coin Promo, base seconds only for a guest). Books **Cash Revenue** (both reporting views are rebuilt) with the promo split still reported as Free Time Dispensed. Writes a `rejection_credit` Alert plus a `rejection_credits` detail row, never a coin transaction. Creditable for 30 days up to a count cap, and irreversible. Supersedes ADR-0021 and amends ADR-0052. |
| [0070](0070-credit-the-pulse-sum.md) | **Credit the pulse sum**: every positive closed Coin Batch credits checked `pulse_count × 100 cents`, never a **Pulse Map** lookup, which took only 39.6 % of inserted money because an over-count or a merged pair matches no key and credits ₱0. Runtime Coin Source configuration excludes the Pulse Map; `Unmapped` and live mismatch rejection production are removed, while historical Rejection Credit remains supported. S1 reports timing as unavailable; later filtered timing reports plausibility without withholding credit. |
| [0071](0071-event-driven-coin-reader.md) | **Event-driven coin reader**: the 30 ms `thread::sleep` poll is blind ~30 ms out of every ~30 ms *permanently* and silent about it, so the reader moves to `WaitCommEvent`/`EV_DSR` on a **directly-opened overlapped handle** (FFI on `serialport`'s synchronous handle is rejected — no timeout, and it blocks the Set Pin write). **No fallback**: where events are unavailable the coin path refuses loudly. 20 ms heartbeat governs the idle line; the **two-sided filter (45 / 28) moves into the reader** before `observe()`; `high_since` is deleted in favour of the filter's own LOW span; and a stall **taints the measurement, never the credit**, over the batch span widened by `min_high` at each end. Reports a rate **and** a maximum. |
| [0072](0072-credit-the-straddling-train.md) | **Credit the straddling train**: inhibit cannot stop a train already running, so every mid-train close today credits half a coin and looks correct. One term — `if set_pin_asserted \|\| self.has_buffered_pulses()` — makes the reader's gate permeable to a train it already admitted, and the buffer *is* the in-flight predicate. Inhibit stays immediate (that is what bounds the tail to one 4.11 s train and prevents chaining); the drain becomes state-driven under a **6 s cap as a fault trip, never a knob**; draining is published as a state; the trait splits into `inhibit_and_discard` / `inhibit_and_drain`; the port-open phantom is fixed at its source. Refines ADR-0023 — its in-flight rule keeps its intent and loses its premise. |
| [0073](0073-owner-coin-surface-is-a-report.md) | **The owner's coin surface is a report, not a control panel** — a value set by the acceptor's physics is not a site setting. Four blocks (Connection / Acceptor Verification / Acceptor Health / Advanced-reference), one Save button. Calibration becomes **Verification** with a count-and-width pass condition, advisory except on outright failure; pesos-per-pulse and the Pulse Map go read-only; the filter parameters and **`inter_coin_gap_ms`** are demoted to read-only reference with no gate; the event list becomes rates. Coin Pin Polarity is **redefined** (`normally_open` finally means idle-low/pulse-high) and migrated **by value** so observed behaviour is preserved exactly. |
| [0074](0074-owner-session-hardening.md) | Every Owner Session gets an HttpOnly SameSite cookie, CSRF and Origin checks, 30-minute human-idle and 12-hour absolute expiry, token rotation, and socket cancellation. HTTP remains an accepted risk on the isolated admin network. |
| [0075](0075-web-admin-remote-control.md) | The Web Admin embeds noVNC behind an in-process Rust bridge to TightVNC. One silent shop-wide Remote Control Session may view or control any configured PC, with server-owned targets, PIN step-up, transient credentials, bounded lifecycle, and append-only audit. |
| [0076](0076-client-reachability-mismatch-monitoring.md) | Windows Admin monitors Host, Client, Host Probe, and Client Guard coverage for visible registered PCs. Durable PC Monitoring Incidents produce local Alerts and optional outbound-only Telegram delivery without changing PC, session, money, time, or Points authority. |
| [0077](0077-client-recovery-escalation.md) | **Client Recovery Escalation**: the Client Guard also relaunches an absent Client on a level check, not only on a dropped pipe, and gains one outbound MAC-identified poll to `:3210`. When a mismatching PC has a polling Guard that reports no Client and at least one failed relaunch, the Admin powers that PC off after an owner-set Escalation Delay, ends its session as `escalated_power_off`, and leaves balance, time, and Points untouched. Off by default, PIN-gated, one power off per PC per hour. Narrows ADR-0076. |
| [0078](0078-support-bundle.md) | **Support Bundle**: Diagnostic Forwarding runs always from Client and Client Guard into Admin's rotating files (never SQLite) and the Diagnostic Request tops it up on demand; the Client dials its own endpoint while the Guard widens its poll; release-only with an explicit development opt-in. One redacted Markdown bundle with a Verdict serves it from the Web Admin. Closes ADR-0016's open forwarding consequence and supersedes its Logs-screen viewer. |
| [0079](0079-client-local-tamper-kill-handoff.md) | **Local Tamper Kill handoff**: a launch that will not become the runtime validates its Guard report arguments and atomically drops one identity-named file into a bounded inbox beside the authoritative report; the running Client drains it, persists the merged report before removing inbox files, bumps the SSE generation barrier, and clears only on the existing server acknowledgement. Retried deliveries are no-ops by report identity; local acceptance means durably recoverable, never Admin-acknowledged. Hints, never authority — attribution stays the server's (ADR-0048). The process-level Windows harness at this boundary is the shared seam for the startup tickets. |
| [0080](0080-client-startup-arbitration.md) | **Startup arbitration**: one machine-wide, lifetime-scoped ownership object (`Global\OpenPiso-Client-Runtime`) decides admission atomically before the placeholder, hooks, Guard pipe, Tauri runtime, state writes, or networking. Exactly one participating Client runtime per shop PC; a loser is inert, hands any Guard report through the ADR-0079 inbox before a handled-success exit, and a denied or incompatible object is a truthful coordination failure, never silent admission. Release-Windows only; debug and non-Windows stay inert. Revisits the earlier named-mutex proposal with the ADR-0079 handoff that made rejection safe; supplements, never replaces, the exact-child Guard gate. Rollout requires a clean restart into participating binaries. |
| [0081](0081-diagnostics-surface.md) | **Diagnostics**: one gated top-level Web Admin page holds every piece of evidence about the running system — Support Bundle and Diagnostic Request (Client tab), Coin Debug Bundle and Coin Debug Window (Coin tab), Run Records and panic evidence (Server tab) — and retires the Settings **Support** section. **Diagnostics Mode** is a visibility flag and nothing else: capture is unconditional, the endpoints serve any authenticated Owner Session, and it is not a security boundary. |
| [0082](0082-admin-run-records.md) | **Admin Run Records**: Admin writes a Run Record at startup and completes it with an Exit Reason on shutdown, kept as a rolling ten in a JSON file outside the rotating logs; a start with no end is reported as a suspected hard exit. The tracing guard is held and flushed instead of forgotten, and the Client gains a panic hook but no Run Records. |
| [0083](0083-install-telemetry.md) | **Always-on install Telemetry**: token-bearing Admin builds send one anonymous `admin_daily_summary` per UTC+08:00 reporting day (Admin version, active-PC counts, allowlisted envelope) to PostHog Cloud US over plain `reqwest`, keyed by a random Installation ID that backups exclude. No owner opt-out; PostHog sees source IPs in transit before discarding them, and past events cannot be individually erased. No person profiles or GeoIP; queued in a SQLite outbox like Telegram delivery and kept off authority paths. No PostHog SDK, no webview capture, no Client egress; builds without a token cannot send. |
| [0084](0084-attendance-rewards.md) | **Proposed — Attendance Rewards**: separate Account-only daily time liability; immutable Check-Ins, versioned settings and eligibility, monotonic calendar authority, authenticated full-month claims, deadline-derived expiry and auditable reconciliation. S1–S6 implementation recorded; canonical automated assertions pass; S7 manual/release merge-gate evidence pending. |
| [0085](0085-migration-version-guard.md) | **Migration-version guard**: before the fresh-install marker, Pre-Migration Backup, any migration, or seed, Admin refuses a history with an unknown/newer version or a gap in `1..N`; version 0 stays the fresh-install marker. No direct downgrade: return to an older Admin via its matching Pre-Migration Backup. |
| [0086](0086-admin-app-update.md) | **Admin App Update**: Owner-initiated, minisign-signed stable updates from public `openpiso` (checked every 6h, default on); Compatible Rollback only within the same Schema Version; schema-raising updates need acknowledgement; brief Client lock on restart accepted. |

| [0087](0087-source-available-license.md) | **Publish source under PolyForm Shield 1.0.0**: public, source-available (not OSI open source); shops may run their business; competing products, including resale as a substitute, are restricted. Supersedes ADR-0086 source privacy. |
| [0088](0088-spin-password-confirmation.md) | **Spin Password Confirmation**: owner-toggled (off by default); each paid spin re-enters the Account password, verified by the server before the point is charged. Wrong attempts share the Account Login Throttle. Free spins in a chain never prompt. Amends ADR-0012 and ADR-0046. |
| [0089](0089-client-ui-state-machines.md) | **Client UI state machines**: every new or edited `apps/client` flow is a discriminated-union State/Event with a pure exhaustive `reduce`, effects in a thin runner, machine in plain `.ts`. Hand-rolled, no library. **Amended 2026-10-20:** Web Admin Login and Manual Adjustment opt in under `apps/web-admin/src/lib/machines/`; no blanket migration. |
